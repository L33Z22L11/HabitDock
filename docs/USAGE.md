# 知时 · HabitDock

独立 Android 桌面组件：根据一天中的时间、星期和最近使用频率，自动推荐你可能要打开的 App。保留现有桌面，无云端服务、广告或分析 SDK。支持 Android 8.0+，已在 Android 15 模拟器验证。

## 使用

1. 从 GitHub Releases 下载并安装 `HabitDock-0.5.0.apk`。
2. 打开「知时」，先在右上角「设置 → 不推荐的应用」中勾选不希望出现的 App；勾选立即生效，无需保存。
3. 开启系统「使用情况访问权限」。首次读取系统仍保留的历史，不足时会逐渐学习。
4. 点击「设置 → 组件样式」右侧的 4×2 或 2×2，在默认布局编辑页底部点击添加；也可长按桌面 → 小组件 →「知时 · 智能推荐」。
5. 组件默认采用 5×2 布局：9 个 App＋最后一格「更多／更新时间」。点击图标由桌面通过目标应用的 PendingIntent 直接启动，不经过知时中转，也不会触发补刷。点击更多进入与 App 图标相同的主界面，查看全部推荐；未到刷新间隔时保留上次推荐。应用图标随组件尺寸适配；更多入口的三点单独缩小，图形容器不超过 28dp。三点始终在格子正中，更新时间以 35% 不透明度紧贴其下方；时间仅用于展示，不再触发手动刷新。支持缩放的桌面可长按调整已有组件的大小。
6. 设置按「推荐机制」「样式设置」「权限与数据」「关于」分组。样式设置提供图标样式、组件样式和主界面样式；组件样式右侧的 4×2／2×2 分别打开对应默认布局，在编辑页底部添加到桌面。主界面样式的应用主题分成两组分段选择器：明暗模式「系统／浅色／深色」，主题配色「默认／自动／自定义」。系统只控制跟随系统深浅色；默认使用应用配色；自动在启用自定义图片时从图片取色，否则跟随设备配色；自定义以手选颜色生成配色。三种配色均可搭配三种明暗模式；自动与自定义动态配色需 Android 12 及支持动态配色的设备。主界面开启「壁纸背景」时，使用白字与整页黑色遮罩；「背景透明度」可调 0%–100%，默认 80%（轻微压暗），实时预览并支持恢复上次／默认。组件可独立选择跟随系统、浅色、深色、设备配色或自定义背景色，并调整 0%–100% 背景透明度，不影响图标和更多入口的不透明度。样式预览使用真实桌面壁纸；标准小组件没有通用的宿主背景模糊接口。
7. 排除与固定应用选择器采用双栏、应用图标、右上角展开名称／包名搜索，标题显示已选数量；已选项仅在离开后重新进入时置顶，勾选和搜索期间保持本次进入时的顺序；选中卡片上下各缩进 2dp，与横向间隔一致；图标和勾选标记左右边距对齐。原生复选框与整项均可点击，修改立即生效，切换主题保留选择。推荐主界面采用双栏，行距更宽松。
8. 无底部导航；右上角齿轮进入设置，「不推荐的应用」位于设置首项。顶部返回与系统返回都按「不推荐 → 设置 → 推荐」返回，保留筛选内容。推荐默认行高至少 68dp、图标 44dp、应用名 16sp，随字号与理由行数调整；不推荐列表仍是紧凑的 48dp 行高。大字体超过 1.35 倍时改为单栏。
9. 「设置 → 图标样式」统一控制推荐页、应用选择器、操作气泡与桌面组件的图标轮廓。「圆角模式」使用紧凑滑动选项选择普通圆角或超椭圆：普通圆角范围 0%–100%（默认 40%）；超椭圆参数 2.0–8.0（默认 4.0），两种参数分别保留。图标包列表只保留一个「应用原图标」入口，选择原图标后下方显示「图标填充：关／白色／自适应」，不再提供任意填充颜色；旧自定义填充色迁移为自适应。图标包已适配图标不叠加原图标填充，未适配原图标保留填充与缩放设置。修改即时生效，并支持恢复上次或默认。
10. 主界面长按应用弹出贴近该项的小气泡菜单，图标在上、文字在下，横排且随可用宽度和字体大小换行：固定／取消固定、不推荐、应用信息、分享安装包。包名右侧的小灰色复制按钮可复制完整包名。气泡顶部一行展示小图标、应用名和包名，名称与包名超长自然省略。气泡先测量内容高度，底部放不下时显示在应用上方，并避让系统栏与键盘。选择菜单项后才执行；普通点按直接打开应用。
11. 标准 Android 组件长按由桌面接管，用于移动或调整大小，没有应用可用的长按回调；部分厂商桌面禁用了缩放，即使组件声明支持也不会出现调整框。可从更多进入主界面后长按；或在该组件的布局设置开启「点按图标显示操作菜单」，通过同一个主界面弹出同一菜单。默认不开启。
12. 分享安装包使用 AndroidX FileProvider 和系统分享面板，只授予所选文件的临时读取权限，不含账号和应用数据。单 APK 原样导出；分包应用导出包含全部已安装 APK 和说明的 ZIP，接收方需支持分包的安装器。仅包含当前设备已安装的分包，不含另外下载的资源，也不保证跨设备兼容。临时文件存于应用缓存，每次打开应用或准备分享时，顺带清理超过 24 小时的导出文件。近期文件保留以供接收方读取；不新增定时清理任务，不清除推荐记录或设置。

13. 「设置 → 推荐数量」默认 20 个，可用滑杆与加减按钮选择 1–100 个，确认后保存。只限制智能推荐，固定应用另计且数量不限。修改后立即应用于推荐页、预览和组件，不改排序或上次推荐更新时间；组件最多显示布局容纳的数量，有多少推荐就展示多少，不凑满上限。
14. 「设置 → 开源仓库」独立打开 GitHub 项目。「关于知时」标题后显示当前 v 版本号，描述显示「已学习 X 天 · X 条记录」，点按可查看版本与应用说明，弹窗标题与正文之间展示应用图标，并跟随全局圆角设置。学习天数指现有记录中实际有使用记录的天数；进入设置只读取本地统计，不改变推荐时间。关于右侧的「检查更新」按钮仅点按时请求最新正式版信息：有新版弹窗提示，选择「前往下载」打开对应 Release 页面；稍后再看时，同一个按钮变为「查看更新」。无更新时提示已是最新正式版；网络失败可重试或直接打开版本页面。不会后台检查、自动下载或安装。

无需白名单。默认学习有桌面启动入口的 App，排除自身和桌面启动器；隐藏应用仍正常学习。固定应用数量不限；可选择星期和时间预览不同场景，预览不改变桌面实时推荐。工具栏使用 History 时钟箭头图标开启预览；预览中刷新按钮高亮，点击即可退出预览、回到此刻。

桌面和 Dock 已有的图标需要手动加入「不推荐的应用」；本应用不读取其他桌面的私有布局。

「组件样式」右侧提供 4×2、2×2 按钮，点击进入对应默认布局编辑页，底部添加按钮再唤起桌面添加确认。新组件分别使用「组件样式 → 4×2 默认布局 / 2×2 默认布局」，添加后可独立修改名称、内部行列、图标比例和更多入口。取消系统添加不会修改现有组件。桌面组件选择器也提供这两种占格；实际占格由桌面网格和剩余空间决定。4×2 内部出厂默认 5 列、2 行，2×2 默认 3 列、3 行；两套默认设置互不影响，与已有实例独立。已有组件的占位不会因更新被强行修改。构建时自动生成两种尺寸各自的静态预览图，兼容会过滤无预览组件、或添加确认框只接受位图预览的桌面。支持自定义请求预览的桌面会展示当前默认内部布局。

「组件样式」下拉框右侧的「重命名」可分别给已有组件命名，留空恢复默认名称，不影响推荐或布局。名称用于设置里区分各个实例；桌面自行绘制的外置标题由桌面管理，Android 没有修改其每个实例名称的通用接口。

## 主界面样式与推荐理由

「原生」由系统实时提供背景；「兼容」通过 Android 壁纸读取 API 缓存静态图片，「自定义」通过系统图片选择器导入图片。两种图片模式分别保留各自图片，贯穿主界面、设置、选择器和主界面样式预览页；图标和组件样式页的预览区域仍展示桌面原生壁纸。图片模式提供 0–100% 应用内模糊，后台计算并保留上一帧，不模糊图标和文字；原生模式的模糊需要 Android 12+ 且设备启用系统窗口模糊。

兼容模式不是绕过系统权限：Android 13+ 需用户在系统页主动授予「所有文件访问」，旧系统需存储读取权限。只在点击读取时访问壁纸，不扫描其他文件；动态壁纸无法作为实时画面缓存。自定义图片仅使用选择器授予的图片读取权限。图片获取／更换、透明度和模糊集中在同一行；点击百分比按钮展开小滑杆，调整即时生效，点击外部收起。大字体时操作自动分行。图片副本保存在应用私有目录，不上传；更换桌面壁纸后可手动重新获取。壁纸图与自定义图分开保存，恢复上次也恢复本次编辑前的图片选择。


「设置 → 主界面样式」「壁纸背景」直接选择「关／原生／兼容／自定义」：关闭时使用主题，其余模式按对应来源显示背景。原壁纸配色设置迁移为跟随应用样式。图标大小 32–64dp、应用名大小 14–20sp。置顶应用在图标右下角显示角标。应用项不绘制卡片底色，采用适中行距和点击涟漪；桌面壁纸模式的顶栏使用淡黑色透明背景，时间与操作图标为白色，滚动条为浅色；不额外给图标和文字添加阴影。主界面布局单独调整；图片背景贯穿应用内页面，组件在桌面上的大小、透明度和配色仍由组件样式独立控制。图标样式页采用当前选择的组件实际配色，以两个 4×2 组件预览不同应用图标；第一块显示 10 个应用槽位，不显示更多按钮，第二块保留更多入口。

推荐理由用可点击、可拖动的滑动分段控件选择「不显示」「简略」「详细」；取消拖动保留原选择。简略沿用时段、常用等说明；详细在样本足够时显示真实记录的近期打开次数，或星期、时段习惯；样本不足继续显示学习状态，不编造次数。次数仍是系统前台事件合并后的估算，不改变推荐分数和排序。

「显示隐藏应用」默认关闭。打开后，隐藏应用按真实使用记录参与主页正常排序，图标和文字半透明，并显示独立隐藏角标；推荐理由仍遵守所选显示模式。隐藏只影响展示：继续采集与学习，保留历史；桌面组件始终过滤隐藏应用。推荐数量上限仍然生效。

样式调整立即保存；「重置」提供恢复本次进入前的设置或恢复默认，旋转屏幕后仍保留本次恢复点。组件样式页可在真实桌面预览中检查背景与图标的效果。预览和控件一起滚动，顶部工具栏固定；壁纸固定在屏幕原位，透过滚动中的预览区域显示对应位置。普通页面之间保留系统预测性返回；涉及壁纸的应用内页面间返回按整页边界处理跟手、取消与提交，上一页不会通过预览孔洞提前露出。

## 隐私

- 隐藏名单优先于固定项、时间推荐、冷启动和备用排序的默认展示；桌面组件不会用隐藏应用补位。
- 加入隐藏名单只改变展示，不清除已有记录或停止采集；主界面和组件立即刷新。升级后首次同步会补录系统仍保留的可用历史，仍遵守「重新学习」的截止时间；之后继续按正常增量窗口学习。
- 仅存包名和前台打开时间，最多保留 60 天。数据保存在应用私有 SQLite 中，不读取应用内部内容。
- INTERNET 权限仅用于用户主动检查 GitHub 正式版更新，通过 HTTPS 请求公开版本信息，不传应用列表、包名、习惯记录、账号或设备标识。推荐和学习完全离线；无后台网络任务、无障碍服务、定位权限或分析 SDK。关闭云备份及设备迁移备份。
- 「清除学习记录」保留固定和隐藏设置，并设置时间截止点，避免重新导入更早的系统历史。
- 不推荐的应用仍会列在排除设置页面中，方便你取消排除。本工具不负责隐藏系统桌面上的原始 App 图标。

## 耗电与刷新

- 不持续轮询、不运行常驻前台服务、不申请唤醒锁或精确闹钟。
- 使用单个系统 JobScheduler 周期任务，默认约每 30 分钟执行一次，可在「设置 → 更新频率」选择 15 分钟、30 分钟、1／2／4／8／12／24 小时，允许系统批处理及省电延迟。
- 只有存在桌面组件且已授予使用情况权限时才安排周期任务。移除全部组件后取消任务；撤销权限后任务在下次检查时取消。
- 每次增量读取系统事件，带 5 分钟重叠窗口防止漏记并去重。隐藏设置变动只重新生成展示结果，不重置增量采集游标。
- Widget 图标直接启动目标应用，不经过中转 Activity，也不附带刷新任务。应用内推荐列表仍是常规应用内跳转。
- 打开推荐页、点击更多与周期任务共用同一个刷新时钟。未到期时使用上次的历史截止时间、衰减基准和推荐时间，保留推荐顺序及更新时间，进程重启也一样。
- 仅主动点击主界面的刷新按钮立即刷新；组件时间只展示上次推荐生成时间。系统校时、开机、版本升级或样式重绘也遵守刷新间隔。修改固定／排除名单、权限或重新学习立即生效，不受间隔阻挡。强行停止 App 后需再次打开恢复任务。
- 不要求关闭系统电池优化。各品牌系统可能延迟后台刷新，故不承诺准点更新。
- **尚未在实体手机上做长时间电量测量，不能给出实际耗电百分比。**

## 推荐规则

本地可解释的统计模型，不需要大模型或 API Key：

- 时段相似度：75 分钟高斯邻域，跨午夜按环形时间计算。
- 区分工作日/周末，同一星期几进一步加权。
- 历史记录按 14 天半衰期衰减，逐渐适应新习惯。
- 有足够样本时：65% 时段匹配、20% 总使用频率、15% 近期使用；样本不足时平滑回退到频率。
- 排名不是「预测成功概率」。前台恢复事件可能包含同一 App 的页面切换，已做短间隔合并，但打开次数仍为估算。
- 不统计其他用户/工作资料空间；重装后的新历史、旅行时区变化及系统事件保留期限会影响推荐效果。

## 构建

JDK 17、Android SDK 35、Build Tools 35.0.0、Gradle Wrapper 8.11.1、AGP 8.9.2。应用代码使用 Java、Android Views 与 Material Components 1.12.0（Material 3）；安全文件分享使用 AndroidX Core 1.16.0 FileProvider（与当前编译 SDK 兼容）。

macOS / Homebrew：

```sh
brew install openjdk@17 gradle
brew install --cask android-commandlinetools
export JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home"
sdkmanager 'platforms;android-35' 'build-tools;35.0.0'
printf 'sdk.dir=%s/share/android-commandlinetools\n' "$(brew --prefix)" > local.properties
./gradlew assembleDebug lintDebug
sh scripts/test-predictor.sh
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。也可直接用 Android Studio 打开项目。

GitHub Releases 中的 APK 使用固定 release 签名，支持在同签名旧正式版上覆盖更新。本地 ADB 开发包使用 debug 签名，与公开正式包不同。

## 验证

`scripts/test-predictor.sh`：141 项算法/展示过滤、搜索排序、图标尺寸与边缘补全检查，覆盖早晚、工作日/周末、跨午夜、旧习惯衰减、冷启动、过期记录、隐藏展示过滤，以及圆形/圆角渐变、径向渐变、异形和多色回退；图标测试生成 `build/predictor-tests/icon-backgrounds.png` 供外观核对。另含 34 项图片模糊检查，覆盖原图保留、零强度、边界、矩形索引、透明度和半径上限。

Android 集成测试只应在空白测试模拟器运行，会重置本应用的测试数据：

```sh
./gradlew assembleDebug assembleDebugAndroidTest
adb -s <测试模拟器序列号> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <测试模拟器序列号> install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <测试模拟器序列号> shell appops set dev.habitdock GET_USAGE_STATS allow
```
