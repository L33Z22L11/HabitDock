# 知时 · HabitDock 使用说明

知时根据时间、星期和近期使用习惯，在本机推荐可启动的应用。它支持 Android 8.0 及以上，可作为普通应用和桌面小组件使用，也可由用户选择成为系统默认桌面。

## 安装与开始使用

1. 从仓库 GitHub Releases 下载并安装正式版 APK。版本以 Release 页面为准；源码版本见 [version.properties](../version.properties)。
2. 打开知时，进入底部「设置」，按需在「排除应用」中选择不想推荐的应用，在「置顶应用」中选择固定展示的应用。选择立即保存。
3. 在「设置 → 使用情况访问」中前往系统页面授权。知时首次读取系统仍保留的可用历史，之后逐渐学习；未授权时仍可使用应用列表和置顶应用。
4. 按需添加小组件：在「设置 → 组件样式」选择 4×2 或 2×2，编辑默认布局后使用页面底部的添加入口；也可从现有桌面的组件选择器添加。是否出现添加确认或调整大小入口取决于桌面宿主。
5. 如希望以知时作为桌面，在「设置 → 设为默认桌面」中通过系统选择；已设为默认时可用「切换默认桌面」进入系统设置更换。系统选择界面可能因设备而异，取消选择不会更改默认桌面。

正式包使用 `dev.habitdock`，debug 包使用 `dev.habitdock.debug`，两者可并存，数据各自独立。覆盖安装需要包名和签名匹配；旧版使用正式包名的个人 debug 包也需要原签名。固定 release 签名和发布细节见[发布说明](RELEASING.md)。

## 三栏主页

竖屏使用底部导航，横屏使用侧边导航；点击或滑动切换「推荐」「全部」「设置」。在「设置 → 主界面样式 → 默认打开」可选择普通启动时打开推荐或设置，默认是推荐；通过系统桌面入口启动时进入推荐。组件的操作入口也使用同一主页。

- **推荐**：显示按习惯排序的应用和置顶项。点按打开应用，长按打开操作菜单，可置顶／取消置顶、排除、查看应用信息或分享安装包。没有使用情况权限时页面会提示授权。
- **全部**：显示系统可查询到的、具有桌面启动入口的应用。可按名称或包名搜索，筛选全部、系统或非系统应用；右侧 A–Z 和 `#` 索引可点击或拖动以跳转，拖动时其他字母的应用会变暗，并非被排除。
- **设置**：按「推荐机制」「样式设置」「权限与数据」「关于」分组，提供排除、置顶、推荐数量、更新频率、外观、默认桌面、使用情况访问、重新学习及更新检查等入口。

推荐和全部页面标题栏各有「显示」入口，打开各自的底部抽屉，分别调整平铺／宫格布局、图标大小和应用名字号。推荐抽屉还可设置推荐理由「不显示／简略／详细」和「显示隐藏应用」。隐藏应用显示时带半透明标记；小组件始终过滤它们。详细理由中的次数来自合并后的系统前台事件，是估算值。

推荐显示抽屉显示上次更新时间，可选择星期和时间预览；预览只改变主页查看的场景，不改变组件的实时推荐。预览期间主页标题旁会显示预览时间，点击可回到实时并刷新。抽屉中的「立即刷新」也会强制刷新；预览期间按钮为「回到实时并刷新」。

推荐数量默认 20，可设为 1–100；它只限制智能推荐，置顶应用另计。排除优先于组件展示和默认的主页展示，但不会停止学习或删除历史。知时不能读取其他桌面的私有布局，现有桌面或 Dock 上不想重复推荐的应用需自行排除。

分享安装包通过系统分享面板提供临时读取权限，不包含账号或应用数据。单 APK 原样分享；分包应用导出当前设备已安装 APK 的 ZIP，需要接收方使用支持分包的安装器，不保证跨设备兼容。缓存中的旧导出文件在打开应用或准备分享时清理，不设置定时清理任务。

## 小组件

4×2 和 2×2 是桌面占格的默认规格；实际大小和缩放取决于宿主桌面及可用空间。出厂内部布局分别为 5 列×2 行、3 列×3 行，两套默认布局独立。每个已添加组件可在「组件样式」中单独设置名称、内部行列、图标比例、主题、背景透明度、更多入口及更新时间显示；名称用于知时设置内区分实例，桌面外置标题由宿主管理。

多个启用的组件按添加顺序接续取用同一份推荐，不循环重复；更多入口不占推荐名额，推荐不足时留空。组件图标默认直接启动目标应用；更多入口打开主页。桌面通常接管组件长按以移动或缩放，可在主页长按应用，或在组件布局中开启「点按图标显示操作菜单」。

正式版保留旧组件提供者及旧的更多入口，以支持同包名、同签名覆盖更新后的已有组件；已有组件占位不会被主动改写。debug 和正式版是不同包，不能共享或自动迁移组件与数据。组件是否显示、缩放或提供添加预览仍受桌面宿主限制。

组件列表区分默认布局、已启用和「未完成添加或已隐藏」。未完成的绑定可在该入口手动启用；隐藏实例只改变知时的列表和推荐分配，不删除宿主中的系统绑定。宿主未提供足够信息时，组件归属或预览尺寸可能无法准确判断。

## 外观与壁纸

「图标样式」统一设置应用内图标和组件图标的轮廓、图标包及原图标填充。支持常见 ADW／Nova 约定的 `appfilter.xml` 映射；缺失映射、资源损坏或图标包被卸载时回退原图标。未适配图标可单独调整缩放、饱和度、明度和对比度。第三方图标包协议并非 Android 统一标准，不能保证所有图标包或动态效果都可用。

「主界面样式」提供明暗模式、主题配色、默认打开页和「液态材质」开关。液态材质默认开启；可用效果取决于设备提供的能力，不支持时使用回退外观。自动和自定义动态配色需要 Android 12 及设备支持。

「壁纸背景」可选「关」或以下三种来源：

- **原生**：由系统提供实时桌面壁纸；原生背景模糊需要 Android 12 及系统启用窗口模糊。
- **兼容**：主动读取并缓存当前壁纸的静态图片。Android 13 及以上需要用户授予所有文件访问权限，较旧系统需要存储读取权限；更换壁纸后可手动重新获取，动态壁纸不会作为实时画面缓存。
- **自定义**：通过系统图片选择器选取图片，使用选择器授予的读取权限。

图片模式各自保存私有副本，可调整应用内背景模糊；文字和图标不随之模糊。背景透明度和模糊即时调整，图标和组件样式的预览区域展示原生桌面壁纸。组件背景和配色独立设置，标准小组件没有通用的宿主背景模糊接口。样式页可恢复进入页面前的设置或默认值。

## 隐私、权限与刷新

- 使用情况访问用于读取系统前台事件；只保存包名和前台打开时间，最多保留 60 天，存于应用私有数据库，不读取应用内部内容。推荐与学习在本机完成。
- 「重新学习」清除本机使用记录并设置截止时间，避免再次导入更早的系统历史；置顶和排除设置保留。排除仅影响展示，不停止采集。
- 网络权限用于用户主动检查 GitHub 正式版更新；不上传应用列表、习惯记录、账号或设备标识，不后台检查或自动安装。应用关闭云备份及设备迁移备份。
- 兼容壁纸读取只在用户主动获取时访问壁纸；自定义图片使用系统选择器授权。图片副本保存在应用私有目录，不上传。
- 不运行常驻前台服务、持续轮询或申请唤醒锁。存在组件且已授权使用情况访问时使用系统周期任务，默认约 30 分钟，更新频率可设为 15 分钟至 24 小时；系统省电策略可能延迟执行。移除全部组件后取消任务，撤销权限后下次检查时取消。
- 打开推荐页和组件更多入口通常按刷新间隔补刷，未到期保留上次推荐时间；设置变更等会立即更新展示。强行停止应用后需要重新打开以恢复任务。不要求关闭电池优化，未对实际耗电百分比作承诺。

推荐使用时段相似度、星期和近期频率，历史以 14 天半衰期衰减，样本不足时回退到频率。排名不是预测成功概率；系统事件保留期限、重装、时区变化和其他用户或工作资料空间均可能影响结果。

## 构建与验证

需要 JDK 17、Android SDK 35、Build Tools 35.0.0 和项目中的 Gradle Wrapper。设置 `ANDROID_HOME`，或在未入库的 `local.properties` 中设置 `sdk.dir`，然后运行：

```sh
./gradlew spotlessCheck assembleDebug lintDebug
sh scripts/test-predictor.sh
python3 -m unittest discover -s tests -p 'test_*.py'
```

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。Android 集成测试及触摸测试需要可重置应用数据的测试模拟器，命令和开发约束见 [CONTRIBUTING.md](../CONTRIBUTING.md)；历史验证记录见 [VERIFICATION.md](VERIFICATION.md)。这里列出的是可运行的检查，不代表当前工作区已经通过或已在实体设备验证。
